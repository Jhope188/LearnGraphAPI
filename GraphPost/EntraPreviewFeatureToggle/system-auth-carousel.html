Background · Slide 2 of 7

What is System-Preferred
Authentication?

🔐
Automatic method ranking
Entra automatically presents the most secure MFA method the user has registered — passkeys and TAP at the top, passwords at the bottom.
🤖
Microsoft-managed by default
No per-user config needed. When set to "Microsoft managed," Microsoft enables it on their schedule across your tenant.
📱
New: Apply to primary auth too
A preview toggle now extends system-preferred logic to primary authentication — not just MFA step-up.

Discovery · Slide 3 of 7
🔍 Step 1 — DevTools

I flipped the toggle.
DevTools told me the truth.

Enabled "Apply to both primary and multifactor authentication" in the portal, then captured the outbound PATCH request.

PATCH · authenticationMethodsPolicy · Request Payload
systemCredentialPreferences: {
  state: "default",
  includeTargets: [{
    id: "all_users",
    targetType: "group"
  }],
  excludeTargets: [],
  isSystemDefaultPrimaryAuthEnabled: true
}

Experiment · Slide 4 of 7

Looks scriptable.
So I tried Graph Explorer.

Took the exact property from DevTools and ran a PATCH against the same endpoint.

PATCH graph.microsoft.com/beta/policies/authenticationMethodsPolicy
Request Body
{
  "systemCredentialPreferences": {
    "isSystemDefaultPrimaryAuthEnabled": true
  }
}

Clean payload. Valid endpoint. Correct property name from the portal's own traffic. Should work, right?

inforcer
Finding · Slide 5 of 7

Nope. 400 Bad Request.

Microsoft's API returned this immediately — no ambiguity.

400 Bad Request
badRequest · 1289ms
"IsSystemDefaultPrimaryAuthEnabled can only be modified through the Admin UX interface."
Graph API Response · April 2026
What this means: Even though the portal uses this property in its own PATCH call, Microsoft has intentionally blocked programmatic access to it. The API and the UX don't have the same permissions — by design.
inforcer
Takeaways · Slide 6 of 7

Why this matters for
M365 automation

1
Not every portal setting is scriptable
Microsoft intentionally gates certain controls to the Admin UX. DevTools can show you the property — but the API may still block you.
2
Configuration drift risk for automation teams
If your IaC or drift detection tooling reads authenticationMethodsPolicy, this property won't surface through Graph — you need portal-side monitoring.
3
DevTools is still your best friend
Even when Graph blocks you, intercepting portal traffic tells you the exact data model — invaluable for documentation and compliance evidence.
4
Enable it — just do it manually
System-preferred auth is a genuine security uplift. The ranking hierarchy ensures users get passkeys and Authenticator before passwords.
