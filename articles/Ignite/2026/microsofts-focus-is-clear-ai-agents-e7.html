THR1803: Agents are the new service principals

Martina Grom, an MVP for Foundry and M365, took a governance angle on agents. Her question was simple: you would not approve a service principal with no owner, unknown permissions and no retirement process, so why accept that for agents? An agent identity shares the service principal object model, but it holds no credentials of its own because the blueprint does, and one blueprint can sit behind many agent identities. Her advice is an owner on every agent alongside the required sponsor.

The demo made the point. Her Foundry agent had no permissions, and its blueprint had only a federated credential, so it looked locked down. Still, a prompt for HR data came back with results, because the Foundry project's managed identity had been granted access to the whole storage account. Each piece checked out on its own, but nobody had checked the combination. Review the blueprints as well as the agents, and look for managed identities that can still reach data the agent should not.

She closed with containment. Disabling an agent, disabling its blueprint, blocking it with Conditional Access and blocking it in Agent 365 each do different things, and none of them retires an agent. Her checklist before you approve one is identity, authority and reach, with a sponsor and an owner and a plan for retirement.

The Entra MCP: free, and easy to overlook

One identity announcement barely got airtime on stage: the Microsoft MCP Server for Enterprise, which the Entra Ignite post lists as the Microsoft MCP Server for IT Admins and generally available. It is also free. Learn lists no additional license for it. If you have been using Lokka, you can see where this is heading. An Entra MCP that can read your policy and tenant configuration is a huge help to MSPs, because it takes a lot of the pain out of managing M365 across tenants. It is also the clearest example I saw of what Microsoft is doing with AI and automation for admins, and I think it is the most exciting item in my book.

Update since Ignite

Microsoft has already renamed this to the Microsoft MCP Server for IT Admins and moved it to a new https://mcp.svc.cloud.microsoft/admin endpoint. The /enterprise endpoint below still works during a migration window, but new setups should follow the current IT Admins migration guide, which also changes how clients like VS Code get registered (every client now needs its own app registration — Microsoft's Learn get-started guide still describes the older /enterprise flow as of this writing).

Section 03

E7 Is Where Microsoft Is Headed, and Most SMBs Are Still Maximizing Business Premium

Source: Agent 365 and E7 pricing · Defender Suite for Business Premium · Security add-on plans for Business Premium · Microsoft Entra licensing · Conditional Access for agents · Dynamic permissions · Governing agent identities · Default agent inactivity policy · Network data security licensing · ID Governance guest licensing · Tenant Governance licensing · Agent 365 service description

Microsoft is all in on E7, and after a week at Ignite I understand why. The price tag is easy to miss in all the excitement, though. I have seen forward-leaning MSPs ramp up E5 and E7 for their clients, and that is great to see. Most of the MSPs I speak with at Inforcer, though, are still working to get the full value out of Business Premium, and the goal at Inforcer is to make that simpler at scale.

The licensing question came up once the agent identity lifecycle discussion ended. E7. Almost every agent feature needed it, or an Agent 365 license on top of Entra P1 or Microsoft 365 E3. An enterprise can plan for that. For most SMBs it is a big step up. Microsoft is asking everyone to limit and control agents because agents are the next identity threat, and an SMB without E7 has fewer tools to do that with. There is one free starting point. Every tenant gets a default agent inactivity policy with no license required. It notifies sponsors and owners after 60 days of inactivity, disables the agent at 90 days and deletes it at 455. It allows only limited customization, so custom rules for sponsors and reconfirmation still need E7 or Agent 365, but it is worth turning on in every tenant you manage today.

I talked with people new to the field who genuinely wanted to know how to set up Intune and make Autopilot work, how to fix identity mistakes, and where to begin with data governance and Purview. The roadmap was packed, and the foundation and the basics got less airtime next to E7, agents and AI. Those are all good things to build. I would love to see more of "we see you, SMBs, and here is what's coming to Business Premium for you." That gap is where Inforcer can help.

I left Ignite with a clearer mission: help smaller multi-tenant environments get more out of what Microsoft is building.

I still think Business Premium is the end-all for any SMB. If security and data governance are top of mind, I'd add the Defender and Purview add-ons on top of it. That's already a stretch for a lot of smaller budgets, but for anyone taking security seriously I see it as the new middle ground. Past that, the price jumps. Microsoft lists E7 at $99 per user per month and Agent 365 by itself at $15 per user per month, both on an annual commitment.

The Entra Ignite post doesn't say which license any of these features need, so I went to Learn. The pattern holds up. To extend an Entra security control to agents, you need Microsoft 365 E7, or an Agent 365 license on top of at least Entra P1 or Microsoft 365 E3. Business Premium already includes Entra ID P1, and Learn lists it among the plans you can add Agent 365 to. So for an SMB, Conditional Access for agents is a per-user add-on, not a leap to E7. Dynamic permissions is the exception, since E7 is the only plan Learn lists for it. That's why the table below uses two tags instead of lumping everything under "E7."

Source: Ignite 2026 Book of News · BRK348 session page · Session page, From understanding sensitive data to protecting it · Agent 365 service description

I caught BRK348, Microsoft Purview: From understanding sensitive data to protecting it, with Aashish Ramdas and Chui Yeung. The session page on the Ignite hub has the details, and the recording is linked from the slide below.

The Book of News Purview section covers three items, all in preview: faster time to protection through automatic classification and labeling, DLP for Copilot that blocks references to sensitive files even when they are unlabeled, and data security for AI agents on Windows. Section 05

Resource Policy Blocks Changes. Configuration Management Reports Drift

Source: Resource policy overview · Configuration management · Tenant Governance licensing

Tenant Governance is the other piece I wanted to cover, because it speaks directly to multi-tenant management. Knowing what a tenant's configuration should be, and catching it when it drifts, is the most basic job an MSP has. The Entra post bundles "cross-tenant configuration management and resource policy" as one Preview line. Learn splits them. Configuration management detects drift from a baseline. Resource policy evaluates supported Microsoft Graph requests before the change happens and can block it.

PieceStatusNotes
Tenant Configuration Management APIsGASnapshots, baselines, monitors and drift detection. Snapshots are kept for 7 days.
Configuration baseline templatesPreviewReusable baseline definitions across monitors and deployments.
Configuration deploymentsPreviewApply baseline settings to the home tenant or governed tenants.
Cross-tenant monitorsPreviewNeeds an active governance relationship plus delegated permissions and workload access. The relationship alone does not grant every workload permission.
Resource policyPreviewCustom policies are written in Rego. Built-in policies take parameters only. Most operations need an ID Governance plan during preview.

Backup and RecoveryNot statedAutomatically backs up critical identity data, including agent identities and Conditional Access policies, so they can be restored to a known good state.
Backup and Recovery PremiumPreview30-day retention, integrated with Microsoft 365 Backup.
Hard deletion protectionPreviewProtects objects such as Agent IDs from permanent deletion.

Cross-tenant configuration management is included in Tenant Governance Basic, and Premium licenses add monitoring and snapshot capacity. Governance relationships with cross-tenant GDAP work with P1, P2 or ID Governance. Resource policy is the licensing outlier and needs ID Governance in preview. For an MSP that split matters: cross-tenant drift reporting sits in Tenant Governance Basic, while enforcement needs ID Governance on top.

How resource policy behaves

Each assignment runs in doNotEnforce or enforce mode. An enforce assignment can block a request even when another assignment on the same request is in doNotEnforce. It only evaluates new requests, so it never scans or fixes existing resources, and the preview gives you audit events with no aggregated impact report. Learn recommends simulated evaluation first, then doNotEnforce with the audit-log API, then enforce.

Section 06

Intune: Patching and Compliance Are the Foundation, and Speed Is the New Bar

Source: Ignite 2026 Book of News · What's new in Intune at Ignite · Agent 365 service description · BRK404 session page · BRK328 session page

For Intune I followed BRK404, What's New in Intune: Secure, Patch, and Scale, with Eugenie Burrage and Jason Roszak. The recording is below, and the session page on the Ignite hub has the details. The first portal walkthrough starts at 5:16.

The theme of the session was how AI is changing the device landscape. Supporting servers was crucial, but the speed of AI is now shifting the endpoint too, and the Intune team is working to make speed Intune's middle name. They showed improvements to app compliance, updates and patching, and how much faster compliance check-ins and enrollment have become. The question running through it was how fast you can maintain device health, with AI to troubleshoot faster through Copilot for Windows and Project Perception to help teams automate more of what they do. None of that replaces the basics. Patch rings, compliance policies and enrollment still have to be set up correctly in every tenant before AI can speed anything up.
